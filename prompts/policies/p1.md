# Posible incidente P1

Esta política es condicional: considera candidato a P1 solo cuando exista evidencia explícita de caída masiva, indisponibilidad generalizada, afectación de infraestructura crítica, interrupción de un servicio esencial para múltiples usuarios o incidente crítico de seguridad. No lo declares por palabras como «grave», «urgente» o «crítico» sin esa evidencia.

Ante un posible P1, prioriza el escalamiento sobre un diagnóstico largo, usa `prioridad = "alta"` y `requiere_humano = true`, identifica datos críticos faltantes y conserva una confianza coherente. No inventes causa ni cantidad de usuarios afectados, y no afirmes que el escalamiento ya se realizó: la aplicación ejecuta el flujo P1.
